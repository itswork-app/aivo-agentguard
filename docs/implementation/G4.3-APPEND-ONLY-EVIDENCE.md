# G4.3 — Append-Only Evidence and Hash-Chain Verification

**Status:** Implemented on mainline; G3 durable receipt integration added in PR #15  
**Normative sources:** ADR-0004, ADR-0003, EVIDENCE-FORMAT v0.1.0

## Preserved v1 event contract

- The v1 schema identifier remains `agentguard.evidence-v1`.
- `actor_ref` remains a typed `ActorRefV1` object.
- Decision outcomes remain the closed `ALLOW`, `DENY`, and `REQUIRE_APPROVAL` enum.
- Existing fields, sequence semantics, genesis predecessor, and EVENT digest domain remain unchanged.
- G3 adds optional `context_digest`. It is omitted from canonical event payloads when absent, so existing v1 records and the G4.3 golden event digest remain byte-compatible.
- Unknown fields remain rejected.

## Integrity implementation

- `agentguard-evidence` uses the shared `agentguard-canonical` crate and the closed EVENT digest domain.
- Event hashes cover the typed event payload and `previous_event_hash`; `event_hash` is excluded from its own preimage.
- Genesis predecessor is 32 zero bytes encoded as 64 lowercase hexadecimal characters.
- Stream verification checks sequence continuity from 1, tenant and stream identity consistency, predecessor linkage, record schema constraints, and every event digest.
- Corrections are new events linked by `correction_of_event_id`; committed records are never mutated.
- Validation errors are stable categories and do not echo evidence payload contents.

## G3 durable receipt service contracts

The same crate now exposes explicit ports for:
- tenant/stream head reads;
- atomic conditional append against the expected head;
- durable event read-back with commit identity;
- dedicated evidence-purpose receipt signing;
- signed receipt verification and exact event read-back.

A receipt is created only after durable append and exact read-back succeed. Receipt claims bind tenant, stream, sequence, event hash/type, request/action/policy/context digests, storage commit identity, commit time, and evidence key ID.

## Security limits and non-claims

- No concrete database adapter or signing service is included.
- The store interface does not prove linearizability, durability, tenant isolation, backup/restore behavior, or multi-replica safety.
- No production permit signer or authorization-attestation issuer integration is included.
- Hash-chain validity does not prove truth, completeness before ingestion, durable persistence, or external side-effect success.
- Tail truncation and full-stream rewrite require independently retained signed checkpoints.
- A failed receipt signer after event commit does not roll back the event. The current interface has no receipt-recovery-by-event-ID operation; operational reconciliation remains a release gate.
- The runtime MUST NOT issue an ALLOW permit until the exact decision event has a verified durable receipt.

## Required verification

- Preserve the fixed G4.3 event digest vector: `b87836865744006e46c8e3911d7b3f35ce188e6f38aa9df82c559edba22e12a8`.
- Verify that an absent context digest does not change the existing v1 hash.
- Verify that a present context digest changes the event hash and is receipt-bound.
- Test stream mutation, reordering, deletion, duplication, tenant/stream mixing, malformed timestamps/digests, and strict decoding.
- Test conditional append conflicts, durable read-back mismatch, receipt signature failure, receipt substitution, and signer failure.
- Run formatting, Clippy, and all workspace tests.
- Production enablement still requires concrete multi-node storage, crash/recovery and concurrency tests, external checkpoint anchoring, and independent security review.
